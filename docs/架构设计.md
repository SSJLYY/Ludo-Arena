# 飞行棋联机小程序 · 架构设计

> **状态（2026-09 更新）**：本文档是小程序版的原始架构设计（v1.0，2026-08-29）。小程序线已于 v1.19.2 冻结，但本文的三个核心原则被网页版完整沿用，仍有阅读价值：
>
> 1. **服务端权威状态机**——客户端只提交 action，随机数与规则判定全在服务端；
> 2. **seq 版本号 CAS 乐观锁**——并发写冲突的解法，两版一致；
> 3. **`engine/` 规则层前后端共用**——表现与结算跑同一套代码。
>
> 网页版的实际架构见 [README.md](../README.md)；引擎行为的权威描述与后续裁定见 [实现说明.md](实现说明.md)。
>

## 一、技术选型

### 1.1 核心决策：微信云开发（CloudBase），不自建服务器

| 方案 | 上线周期 | 前置成本 | 同步延迟 | 结论 |
|---|---|---|---|---|
| **云开发 + 数据库 watch** | 2-3 周 | 无（免域名/备案/证书） | 200-800ms | ✅ **v1 采用** |
| 云开发 + 定时轮询 | 2-3 周 | 无 | 1-3s | 兜底降级方案 |
| 自建 WebSocket（Java/Go） | 5-7 周 | 服务器 + 域名 + 备案 + HTTPS | <100ms | v2 规模化后再迁 |

理由：飞行棋是**回合制**，玩家一次操作间隔 3-10 秒，秒级延迟无感知。云开发的 `watch` 实时推送足够，且省掉了备案（1-3 周）这个最大的时间黑洞。

### 1.2 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | 原生小程序（WXML/WXSS/JS） | 不上 Taro/uni-app，减少构建链路与包体 |
| 渲染 | **Canvas 2D** 全绘制棋盘 | 棋盘零图片资源，主包可压到 1MB 内 |
| 后端 | 微信云开发 · 云函数（Node 18） | 与数据库同地域，内网访问延迟低 |
| 数据库 | 云数据库（文档型） | 4 个集合，见第三节 |
| 状态同步 | `db.collection().watch()` | 服务端写 → 客户端实时收 |
| 登录 | `wx.login` + 云开发免鉴权 `getOpenId` | 无需自建鉴权 |
| 头像昵称 | 微信「头像昵称填写能力」组件 | 合规要求，不能用 `getUserInfo` |

## 四、同步机制（最关键的一节）

### 4.1 单向数据流

```
客户端 action ──► 云函数 gameAction ──► 校验 + 权威结算 ──► 写 games (seq+1)
                                                              │
                                            数据库 watch 实时推送 ▼
                                        所有客户端收到新快照 → 播放动画
```

**铁律：客户端永远不直接改 `games` 文档，只提交 action；所有随机数和规则判定在服务端。**

### 4.2 并发控制：seq 乐观锁（CAS）

云函数中用条件更新避免并发写冲突：

```javascript
// cloudfunctions/common/lock.js
const _ = db.command;

async function casUpdate(gameId, expectedSeq, patch) {
  const res = await db.collection('games')
    .where({ _id: gameId, seq: expectedSeq })
    .update({ data: { ...patch, seq: _.inc(1), updatedAt: Date.now() } });
  if (res.stats.updated === 0) throw new Error('SEQ_CONFLICT');  // 客户端重试
}
```

客户端提交 action 时带上本地 `seq`，冲突则自动重拉快照并重试（最多 3 次）。

### 4.3 watch + 心跳兜底

```javascript
// services/sync.js 核心
const watcher = db.collection('games').doc(gameId).watch({
  onChange: (snapshot) => applySnapshot(snapshot.docs[0]),
  onError:  (err) => { watcher.close(); setTimeout(reconnect, 1000); }
});

// 兜底：watch 静默失败时，3 秒轮询兜底
const guard = setInterval(async () => {
  if (Date.now() - lastSnapshotAt > 3000) await fetchSnapshot();
}, 3000);
```

### 4.4 掉线处理（决定体验生死）

| 场景 | 处理 |
|---|---|
| 玩家切后台 / 断网 < 30s | 保留座位，其他玩家看到「断线中」灰标 |
| 断线 > 30s | **自动切换为 AI 托管**（`isHosted = true`），对局继续不卡死 |
| 玩家回归 | 检测到心跳 → 自动接管回座位，弹「已接管」提示 |
| 房主掉线 | 房主权限自动转移给下一个真人玩家 |

> 这条不做，四个人玩一半掉一个就整局报废，是留存杀手。**必须做。**

## 五、飞行棋规则定义（v1，需你确认）

### 5.1 棋盘

- 主环 **52 格**，正方形每边 13 格
- 四角起飞点：红 0 / 黄 13 / 蓝 26 / 绿 39
- 每方 4 架飞机，归航道 **5 格**
- 位置编码 `rp`（相对步数）：
  - `-1` = 基地（未起飞）
  - `0` = 起飞点
  - `0 ~ 51` = 主环行进（绕一圈 52 格）
  - `52 ~ 56` = 己方归航道
  - `57` = 终点（HOME）
- 绝对格位：`absIdx = (startOffset[color] + rp) % 52`，仅 rp ≤ 51 时有效

### 5.2 行动规则

| 规则 | v1 定义 |
|---|---|
| 起飞 | 掷出 **6** 才能从基地进入起飞点，并获得一次额外掷骰 |
| 连掷 6 | 最多连掷 3 次，第 3 次仍为 6 则本回合作废（防无限连掷） |
| 撞子 | 落点有敌方飞机（非安全格、非叠子）→ 敌机回基地，己方获得一次额外掷骰 |
| 叠子 | 己方两架同格 → 叠放显示；敌方撞到叠子，两架一起回基地 |
| 跳格 | 落点是与己方同色的格子 → 前进到下一个同色格（+4 步） |
| 安全格 | 四角起飞点为安全格，敌方飞机不可被撞 |
| 终点 | **必须精确点数到达**，超出则该飞机本回合不可移动（避免倒退挫败感；可通过 `needExactFinish=false` 切换为「弹回」模式） |
| 胜负 | 4 架飞机全部到达终点即完成，按完成顺序排名；先完成者胜 |
| 无子可动 | 自动跳过，不消耗额外掷骰 |

**v1.1 再加**：飞行箭头（同色格飞跃 12 格）、道具卡、观战席、房间内表情互动。

### 5.3 出牌顺序

座位 0 → 1 → 2 → 3 顺时针，固定顺序。掷 6 或撞子后由**同一玩家**继续。

## 六、AI 设计

### 6.1 决策算法：启发式评分

对每架「可行动飞机」模拟落点并打分，取最高分：

```javascript
// engine/ai.js
const WEIGHTS = {
  kill:        100,   // 撞子：按敌方进度加权 × (1 + enemyRp / 57)
  reachHome:   120,   // 直接到达终点
  enterLane:    40,   // 进入归航道（安全区）
  takeOff:      35,   // 从基地起飞
  landSafe:     20,   // 落在安全格 / 己方同色格
  stack:        15,   // 与己方飞机叠子
  jumpGain:      2,   // 每跳 1 格
  progress:      1.5, // 每前进 1 格
  underdog:     10,   // 补偿：优先推进落后的飞机 × (1 - rp/57)
  riskPerDist: -30    // 被撞风险：落点后方 1-6 格内有敌机时，按距离衰减扣分
};

function scoreMove(plane, dice, gameState, seat) {
  const landing = simulateLanding(plane, dice, gameState, seat);
  if (!landing.legal) return -Infinity;
  let s = 0;
  if (landing.killed.length)  s += WEIGHTS.kill * (1 + landing.killedRp / 57);
  if (landing.rp === 57)      s += WEIGHTS.reachHome;
  if (landing.entersLane)     s += WEIGHTS.enterLane;
  if (plane.rp === -1)        s += WEIGHTS.takeOff;
  if (landing.isSafe)         s += WEIGHTS.landSafe;
  if (landing.stacked)        s += WEIGHTS.stack;
  s += landing.jumpGain * WEIGHTS.jumpGain;
  s += (landing.rp - plane.rp) * WEIGHTS.progress;
  s += (1 - landing.rp / 57) * WEIGHTS.underdog;
  s += WEIGHTS.riskPerDist / landing.threatDistance;
  return s;
}
```

### 6.2 难度档位

| 档位 | 策略 | 目标体验 |
|---|---|---|
| 1 简单 | 最高分 + 随机噪声 ±40，30% 概率选次优 | 让新手赢得轻松 |
| 2 普通 | 纯最高分 | 势均力敌 |
| 3 困难 | 最高分 + 一步前瞻（模拟下回合被撞概率），25% 概率触发 | 有压迫感 |

### 6.3 AI 行动节奏

服务端推进，客户端只播动画：

```
玩家点击「掷骰」→ gameAction(ROLL)
   ├─ 服务端算随机数 → 写 dice，phase=selecting
   ├─ 若 movablePlanes.length === 1 → 自动执行移动（省一次点击）
   └─ 若当前座位是 AI → 服务端延迟 800ms 后自动 select + move，循环直到换手
```

AI 回合全程由服务端串行推进，客户端连续收到几次快照，按 `lastAction` 队列依次播放动画。**服务端一次 `gameAction` 调用内跑完 AI 的整回合**，避免多次网络往返。

## 七、页面与交互设计

### 7.1 大厅页 `pages/hall`

| 元素 | 行为 |
|---|---|
| 「创建房间」 | 弹出配置：是否设密码、AI 难度、规则开关 → 生成 6 位房号 → 进房间页 |
| 「加入房间」 | 输入 6 位房号 → 有密码则弹密码框（错误 3 次锁定 60 秒） |
| 「快速开始」 | 1 人 + 3 AI，直接开局（**降低试玩门槛，拉新关键**） |
| 「继续上局」 | 读取 `users.lastRoomId`，对局未结束则一键回归 |

### 7.2 房间页 `pages/room`

四宫格座位卡，每张卡三态：

- **空位**：显示「+ 邀请好友」/「+ 加个电脑」
- **真人**：头像 + 昵称 + 在线状态；房主可踢人
- **AI**：机器人图标 + 难度徽章；房主可切换难度 / 换成空位

底部主按钮（房主视角）：

- `真人数 + AI 数 < 4` → 按钮置灰，提示「还需 N 位玩家」
- `= 4` → 高亮「开始游戏」

座位卡操作：**只有房主可改 AI 配置**，避免互相踢来踢去。

### 7.3 对局页 `pages/game`

- Canvas 2D 绘制棋盘（正方形，边长 = `min(screenWidth, 320px)`）
- 骰子：3D 感的 2D 翻滚动画，600ms
- 飞机移动：逐格跳动，每格 120ms；撞子时敌机「飞回基地」抛物线动画
- 顶部：4 个玩家条（头像 + 已完成飞机数 + 当前高亮）
- 底部：骰子按钮 + 提示语（「轮到你了」/「等待 小明 行动…」）
- 音效：骰子、移动、撞子、胜利，默认开启，可静音

## 八、获客与分享设计

| 触点 | 实现 | 目的 |
|---|---|---|
| 房间分享卡片 | `onShareAppMessage` 带 `roomId`，标题「我开了飞行棋房间，房号 886644，来战！」 | 微信群直接进房 |
| 自定义分享图 | Canvas 2D 生成海报 → `wx.canvasToTempFilePath` → `imageUrl` | 提升卡片点击率 |

## 九、上线合规清单（最容易踩坑的部分）

| 类目选择 | 「游戏」→「休闲游戏」 | 🔴 选错直接驳回 |
| 版号 | 纯休闲玩法、无内购/无虚拟货币，**不需要版号**；一旦加内购必须补 | 🟠 |
| 隐私协议 | 小程序后台配置《用户隐私保护指引》，用到头像昵称必须声明 | 🟠 |
| 头像昵称 | 必须用 `<button open-type="chooseAvatar">` + `<input type="nickname">` | 🟠 |
| 内容安全 | 房间名/昵称用 `msgSecCheck` 过一遍（v1.1 加） | 🟡 |
| 性能 | 主包 < 2MB（我们目标 1.5MB），首屏 < 3s | 🟡 |

> **第一件事先确认主体资质。** 如果目前只有个人主体，先去注册个体工商户（1-3 天下证），否则做完也上不了架。

## 十、开发排期（3 周）

| 阶段 | 工期 | 交付物 | 验收标准 |
|---|---|---|---|
| **P1 房间系统** | 5 天 | 4 个集合 + 5 个房间云函数 + 大厅页 + 房间页 | 4 台真机能同时进房、密码校验通过、座位状态实时同步 |
| **P2 对局引擎** | 6 天 | `engine/` 规则层 + gameAction 云函数 + Canvas 棋盘 + 动画 | 1 人 + 3 AI 能完整打完一局，规则无 bug |
| **P3 AI 与稳定性** | 4 天 | AI 三档难度 + 掉线托管 + 断线重连 + seq 冲突重试 | 中途杀进程 30s 后自动托管，重进能接管 |
| **P4 分享与提审** | 4 天 | 分享海报 + 战绩页 + 音效打磨 + 提审材料 | 过审上架 |

**P1 和 P2 的 engine 层可并行开发**：先写 `rules.js` + `move.js` 并用 Node 跑单元测试（模拟 1000 局自动对战，检查无死循环/非法状态），再接 UI。

## 十一、待确认决策点

进入编码前需要你拍板 4 件事：

1. **主体资质**：企业 / 个体工商户 / 个人？个人主体无法上架游戏类目，需先解决
2. **终点规则**：精确到达（超出不能动，推荐）还是 弹回（超出往回退，更经典但易挫败）
3. **规则范围**：v1 只做「起飞 / 撞子 / 叠子 / 跳格」，飞行箭头（飞 12 格）放 v1.1，是否同意
4. **AI 难度默认值**：默认「普通」还是「简单」（简单更容易留住新手）

## 附录 A：云函数接口契约

| 函数 | 入参 | 出参 | 说明 |
|---|---|---|---|
| `roomCreate` | `{ password?, settings }` | `{ roomId, roomNo }` | 生成不重复 6 位房号，冲突重试 |
| `roomJoin` | `{ roomNo, password? }` | `{ roomId, seatIndex }` | 校验密码，自动分配空位 |
| `roomSeat` | `{ roomId, seatIndex, action, aiLevel? }` | `{ ok }` | 入座/离座/切 AI/改难度，仅房主可操作他人座位 |
| `gameStart` | `{ roomId }` | `{ gameId }` | 校验 4 座已满、全 ready |
| `gameAction` | `{ gameId, action, payload, seq }` | `{ ok, seq }` / `{ err: 'SEQ_CONFLICT' }` | ROLL / SELECT_PLANE，AI 回合内部串行走完 |
| `gameHeartbeat` | `{ roomId, gameId }` | `{ ok }` | 10s 一次，更新 lastSeen |

## 附录 B：错误码

| 码 | 含义 | 客户端处理 |
|---|---|---|
| `SEQ_CONFLICT` | 状态版本冲突 | 重拉快照 + 自动重试（≤3 次） |
| `ROOM_FULL` | 房间已满 | Toast 提示，回大厅 |
| `ROOM_NOT_ENOUGH` | 人数不足 4 | 主按钮置灰 |
| `WRONG_PASSWORD` | 密码错误 | 提示剩余次数，3 次锁 60s |
| `NOT_YOUR_TURN` | 非当前行动方 | 忽略，等快照 |
| `GAME_ENDED` | 对局已结束 | 跳转战绩页 |
