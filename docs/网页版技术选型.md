> 日期：2026-08-31 ｜ 目标：在 2C2G 腾讯云服务器上部署可联机的飞行棋网页游戏
>
> **状态（2026-09 更新）**：这是立项时的决策记录。方案 A（Node.js + ws）已落地并迭代至 v44，但与本文有几处**实现差异**，以实际为准：
>
> | 立项方案 | 实际实现 | 原因 |
> |---|---|---|
> | better-sqlite3 持久化 | **JSON 原子写**（tmp→rename） | 宿主 CentOS 7 glibc 2.17 编译不了 Node 原生模块 |

>
> 其余决策（Canvas 2D、WebAudio 合成音效、原生 JS 零构建、服务端权威 + seq 防重放）均按本文落地。

## 二、推荐方案：Node.js + ws + SQLite（方案A）

### 为什么选这个

1. **你熟悉 JS** — 比起 Go 上手零成本，比 Java 省内存
2. **2G 够用** — Node 进程 40-60MB，Nginx 约 10-20MB，总占用 <200MB
3. **WebSocket 天然适合回合制** — ws 库成熟稳定，延迟 <50ms
4. **SQLite 零额外进程** — 文件数据库，不需要跑 MySQL/Redis
5. **前端零构建** — 原生 HTML/CSS/JS，Canvas 2D 绘棋盘，不用 webpack/vite

### 技术栈明细

```
┌─────────────────────────────────────────────┐

│  │ 无框架    │  │ 音效 · 分享链接            │ │
│  └────┬─────┘  └──────────┬───────────────┘ │
```

## 三、备选方案：Go 单二进制（方案B）

如果你愿意学一点 Go，这是最极致的省资源方案：

| 对比项 | 方案A (Node) | 方案B (Go) |
|---|---|---|
| 后端内存 | 40-60MB | 15-25MB |
| 二进制体积 | node_modules ~150MB | 单文件 ~10MB |
| WebSocket 性能 | 足够（<100 并发） | 极致（万级并发） |
| 你的上手成本 | 零 | 需要看几天语法 |
| 部署复杂度 | 中等（npm install） | 极简（一个二进制文件） |

**建议**：先用 Node 版上线跑通，如果后续日活过千且服务器扛不住，再考虑迁移到 Go。迁移成本不高——规则引擎是纯逻辑，和语言无关。

## 四、不推荐：Java Spring Boot（方案C）

Spring Boot 启动就吃 300-500MB，JVM 堆再吃 512M+。2G 机器上：

```
OS 基础:     ~200MB
Docker:      ~100MB
Nginx:       ~20MB
Spring Boot: ~500MB+
JVM Heap:    ~512M+
─────────────────────
合计:        >1.3GB  ← 剩余不到 700MB，随时 OOM
```

除非你升配到 4G，否则不要在 2G 机器上跑 Spring Boot 全栈。

## 五、前端技术细节

### 5.1 为什么不用 Vue/React

| 因素 | 原生 JS | Vue/React |
|---|---|---|
| 包体大小 | HTML+CSS+JS 总计 <100KB | 打包后 200-500KB |
| 加载速度 | 首屏 <0.5s | 首屏 1-2s |
| SEO | 不需要（游戏页面） | 同左 |
| 复杂度 | 页面少（4个），状态管理简单 | 引入框架杀鸡用牛刀 |
| 维护成本 | 零构建工具链 | 需要 Node 构建环境 |

飞行棋只有 4 个页面（大厅、房间、对局、战绩），原生 JS 完全够用。

### 5.2 Canvas 2D vs DOM 渲染棋盘

**选 Canvas 2D**，理由：
- 棋盘是固定图形（52 格环 + 4 条归航道），不是交互式 UI 组件
- 飞机移动需要逐格动画（每格 120ms），DOM 操作帧率不稳
- Canvas 可以精确控制绘制顺序（底图→格子→飞机→高亮）
- 零图片资源，全部代码绘制，包体极小

### 5.3 音效方案

用 Web Audio API 合成简单音效（骰子滚动、撞子、胜利），不依赖外部音频文件：
```javascript
// 示例：掷骰音效（短促噪声 + 衰减）
function playDiceSound() {
  const ctx = new AudioContext();
  const buf = ctx.createBuffer(1, ctx.sampleRate * 0.3, ctx.sampleRate);
  const d = buf.getChannelData(0);
  for (let i = 0; i < d.length; i++) {
    d[i] = (Math.random() * 2 - 1) * Math.exp(-i / (ctx.sampleRate * 0.05));
  }
  const src = ctx.createBufferSource();
  src.buffer = buf; src.connect(ctx.destination); src.start();
}
```

## 六、通信协议设计

### 6.1 WebSocket 消息格式

所有消息统一 JSON 格式：

```typescript
// 客户端 → 服务端
interface ClientMessage {
  type: 'join' | 'leave' | 'ready' | 'roll' | 'select' | 'chat' | 'heartbeat';
  payload?: any;
}

// 服务端 → 客户端
interface ServerMessage {
  type:
    | 'room_state'      // 房间状态全量推送
    | 'game_state'      // 对局状态全量推送
    | 'action_result'   // 操作结果（掷骰/移动）
    | 'error'           // 错误
    | 'chat'            // 聊天广播
    | 'player_joined'   // 玩家加入通知
    | 'player_left'     // 玩家离开通知
    | 'game_over'       // 对局结束
    | 'pong';           // 心跳响应
  data: any;
}
```

### 6.2 房间路由

```
GET  /api/rooms          → 列出可加入的房间
POST /api/rooms          → 创建房间 { password?, settings }
GET  /api/rooms/:id      → 房间详情
POST /api/rooms/:id/join → 加入房间 { roomNo, password? }
POST /api/rooms/:id/start→ 开始对局
WS   /ws?roomId=:id      → WebSocket 连接（进入房间后升级）
```

### 6.3 安全要点

| 措施 | 实现 |
|---|---|
| 防作弊 | 骰子随机数仅服务端生成，客户端只发「请求掷骰」指令 |
| 防重放 | 每条 action 带 seq 序号，服务端校验递增 |
| 输入校验 | 所有客户端 payload 做 schema 校验（zod 或手写） |
| 房号暴力破解 | 密码错误 5 次锁定该 IP 60 秒 |
| CORS | 仅允许自己的域名 |
| Rate Limit | 同 IP 每秒最多 10 条消息 |

## 七、Docker Compose 部署结构

```yaml
# docker-compose.yml（最终形态）
services:
  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./public:/usr/share/nginx/html:ro
      - ./nginx.conf:/etc/nginx/conf.d/default.conf:ro
      - ./certbot/conf:/etc/letsencrypt:ro
    depends_on:
      - server

  server:
    build: ./server
    ports:
      - "3000:3000"
    volumes:
      - ./data:/app/data          # SQLite 数据文件持久化
    restart: unless-stopped
```

## 八、域名与 HTTPS

你已有 443 端口开放，建议：

1. **买个便宜域名**（`.com` 约 55 元/年，`.cn` 约 29 元/年）
2. **DNS 解析到 129.211.29.228**
3. **用 certbot 自动申请 Let's Encrypt 免费证书**

```bash
# 服务器上一行搞定
docker run --rm -v ./certbot/conf:/etc/letsencrypt \
  certbot/certonly --webroot -w /path/to/public \
  -d yourdomain.com -d www.yourdomain.com
```

没有域名也能用（直接 IP 访问），但分享链接不好看，且无法用 HTTPS。
